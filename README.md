# C++ Linux Epoll Server

基于 C++ 开发的 Linux 多线程 TCP 服务器，使用 epoll I/O 多路复用与线程池处理客户端连接，并通过自定义长度包头协议解决 TCP 粘包、拆包问题。

本项目主要用于学习 Linux 网络编程、Socket 通信、事件驱动模型以及多线程并发处理。

## 1. 项目功能

目前已实现：

- **epoll I/O 多路复用**：监听客户端连接及读写事件。
- **非阻塞 Socket**：配合 epoll 处理网络 I/O，避免单个客户端的读写操作长期阻塞工作线程。
- **线程池**：将客户端事件处理任务交给工作线程执行。
- **EPOLLONESHOT**：避免同一连接在重新激活前被重复通知。
- **动态读写事件管理**：根据发送缓冲区状态决定是否监听 `EPOLLOUT`。
- **发送缓冲区**：保存未发送完成的数据，处理 `send()` 部分发送及 `EAGAIN`。
- **TCP 粘包拆包**：使用 4 字节长度包头识别完整消息。
- **异常处理**：处理连接关闭、非阻塞 I/O 错误及非法长度报文。

## 2. 项目结构

主要模块如下：

| 模块 | 功能 |
|---|---|
| `epollServer` | 服务器初始化、epoll 事件监听、客户端管理 |
| `ThreadPool` | 线程创建、管理与任务执行 |
| `TaskQueue` | 保存待执行任务 |
| `Message` | TCP 消息编码与解码 |
| `main.cpp` | 程序入口 |

### 核心处理流程

```text
客户端连接
    |
    v
epoll_wait()
    |
    v
线程池处理客户端事件
    |
    v
handClient()
    |
    +-- handleRead()
    |      |
    |      +-- recv()
    |      +-- 接收缓冲区
    |      +-- Message::decode()
    |      +-- Message::encode()
    |      +-- 发送缓冲区
    |
    +-- handleWrite()
    |      |
    |      +-- send()
    |      +-- 处理部分发送
    |
    +-- rearmClient()
           |
           +-- EPOLL_CTL_MOD
           +-- 重新激活 EPOLLONESHOT
```

## 3. TCP 通信协议

服务器使用自定义长度包头协议，解决 TCP 字节流没有应用层消息边界的问题。

### 数据包格式

```text
+-------------------+--------------------+
| Header (4 bytes)  | Body (N bytes)     |
+-------------------+--------------------+
| 消息体字节长度     | 实际消息内容        |
+-------------------+--------------------+
```

- Header 使用 `uint32_t`，采用网络字节序。
- Header 记录 Body 的长度，不包含包头自身。
- 当前允许的最大消息体长度为 64KB。

### 编码与解码

`Message::encode()`：

1. 获取消息体长度。
2. 使用 `htonl()` 转换为网络字节序。
3. 将 4 字节包头与消息体拼接。

`Message::decode()`：

1. 判断包头是否完整。
2. 读取消息体长度。
3. 检查长度是否合法。
4. 判断整个数据包是否接收完整。
5. 提取消息体，删除已经解析的数据。

解码函数通过 `Complete`、`Incomplete`、`Invalid` 三种状态区分成功、数据不足和非法报文。

每个客户端拥有独立的接收缓冲区，用于保存尚未解析完成的数据。

## 4. 编译与运行

### 环境

- Linux
- 支持 C++11 或更新版本的编译器
- g++
- Make

### 编译

在项目根目录执行：

```bash
make
```

### 运行

```bash
./main
```

当前服务器使用 TCP 9999 端口。

客户端需要按照项目定义的长度包头协议发送数据。
